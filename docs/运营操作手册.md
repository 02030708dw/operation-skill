# Operation Skills 运营操作手册

适用系统：Windows 10/11、macOS  
适用人员：日常运营人员  
更新日期：2026-07-24

本文只说明安装和日常操作。模型密钥、MYT 控制器、Facebook 登录、Cloudflare R2 凭据等由管理员预先配置，运营人员不要在聊天窗口中发送密码、验证码、API Key、Cookie 或 Secret Key。

## 一、使用前准备

开始前请向管理员确认：

- 已提供模型 API Key，或确认模型接口不需要 API Key。
- 使用点赞和评论功能时，电脑可以访问 MYT 控制器，目标云手机已经人工登录 Facebook。
- 使用视频下载功能时，管理员已经安装 Chrome、Node.js、`yt-dlp` 等依赖。
- 使用 R2 上传功能时，管理员已经配置 Cloudflare R2 存储桶和凭据。
- 只下载、点赞、评论或上传已获授权的内容。

如果 Hermes 提示“缺少环境变量”“依赖未安装”“连接失败”或“凭据缺失”，不要自行填写或在聊天中发送密钥，直接把错误截图发给管理员。

## 二、安装 Hermes

Hermes 官方资料：

- [Hermes Agent GitHub](https://github.com/NousResearch/hermes-agent)
- [Hermes 快速开始](https://hermes-agent.nousresearch.com/docs/getting-started/quickstart)
- [Hermes 模型提供商说明](https://hermes-agent.nousresearch.com/docs/integrations/providers)
- [Hermes Skill 使用说明](https://hermes-agent.nousresearch.com/docs/user-guide/features/skills)

### 2.1 Windows 安装

1. 打开“开始”菜单，搜索并打开 **PowerShell**。
2. 复制下面的命令，粘贴到 PowerShell 后按 Enter：

```powershell
iex (irm https://hermes-agent.nousresearch.com/install.ps1)
```

3. 等待安装完成。安装过程中不要关闭 PowerShell。
4. 关闭 PowerShell，再重新打开。
5. 检查是否安装成功：

```powershell
hermes --version
```

能够显示版本号即表示安装成功。

如果系统安全软件拦截 `uv.exe`，不要自行关闭杀毒软件。联系管理员按 [Hermes 官方 Windows 说明](https://github.com/NousResearch/hermes-agent#troubleshooting) 核验并添加安装目录例外。

### 2.2 macOS 安装

1. 打开“终端”。可以按 `Command + 空格`，搜索“终端”。
2. 复制下面的命令，粘贴到终端后按 Enter：

```bash
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
```

3. 等待安装完成。安装过程中不要关闭终端。
4. 让命令立即生效：

```bash
source ~/.zshrc
```

5. 检查是否安装成功：

```bash
hermes --version
```

能够显示版本号即表示安装成功。如果仍提示找不到 `hermes`，关闭终端后重新打开再试。

### 2.3 Hermes 常用启动与检查命令

Windows 和 macOS 使用相同命令：

```text
hermes
```

进入 Hermes 后，可以直接输入中文任务。

常用检查命令：

```text
hermes status
hermes doctor
hermes update
```

- `hermes status`：查看当前模型和组件状态。
- `hermes doctor`：检查安装及配置问题。
- `hermes update`：更新 Hermes。

## 三、配置自定义模型

本项目指定模型：

| 项目 | 填写内容 |
|---|---|
| 类型 | Custom endpoint |
| API Base URL | `https://llm01.mvkbmb.online/v8` |
| API 模式 | `Chat Completions` |
| 模型名称 | `deepseek-v4-flash` |
| API Key | 由管理员提供；不要发到聊天窗口 |

Windows 和 macOS 的操作相同。

1. 在 PowerShell 或终端运行：

```text
hermes model
```

2. 在提供商列表中选择：

```text
Custom endpoint (enter URL manually)
```

3. `API base URL` 填写：

```text
https://llm01.mvkbmb.online/v8
```

4. `API key` 填写管理员提供的 Key。输入时屏幕可能不显示字符，这是正常现象；如果管理员确认接口不需要 Key，则直接按 Enter。
5. `Select API compatibility mode` 选择：

```text
2. Chat Completions
```

6. 如果显示可用模型列表，选择 `deepseek-v4-flash`；如果要求手动输入模型名称，填写：

```text
deepseek-v4-flash
```

7. `Context length in tokens` 直接按 Enter，让 Hermes 自动识别。
8. `Display name` 可填写：

```text
MVKB DeepSeek
```

9. 配置完成后检查：

```text
hermes status
```

确认输出中能看到自定义端点和 `deepseek-v4-flash`。然后运行：

```text
hermes
```

输入“你好，请回复模型连接正常”。能够正常回复即表示模型配置成功。

如果出现 `401`、`403`、`404`、模型不存在或连接失败，不要反复尝试，也不要把 API Key 截图发到群里。将错误文字和发生时间发给管理员。

## 四、安装本仓库 Skill

推荐使用仓库安装。只有无法访问 GitHub 或管理员发放离线压缩包时，才使用 ZIP 安装。

### 4.1 仓库安装方法（推荐）

Windows 在 PowerShell 中执行，macOS 在终端中执行。两边命令相同。

1. 添加仓库：

```text
hermes skills tap add 02030708dw/operation-skill
```

2. 安装下面 5 个 Skill：

```text
hermes skills install 02030708dw/operation-skill/facebook-daily-like
hermes skills install 02030708dw/operation-skill/facebook-daily-comment
hermes skills install 02030708dw/operation-skill/facebook-followed-video-download
hermes skills install 02030708dw/operation-skill/cloudflare-r2-video-upload
hermes skills install 02030708dw/operation-skill/facebook-video-ingest
```

安装时如果要求确认，检查名称正确后输入 `y`。

3. 查看已安装 Skill：

```text
hermes skills list
```

4. 如果 Hermes 已经处于聊天界面，输入：

```text
/reload-skills
```

5. 后续更新 Skill：

```text
hermes skills check
hermes skills update
```

### 4.2 ZIP 压缩包安装方法

ZIP 必须来自管理员或可信的项目仓库。不要安装来源不明的 Skill 压缩包。

#### Windows

1. 解压 ZIP，例如解压到“下载”目录。
2. 在 PowerShell 运行：

```powershell
hermes config path
```

3. 记下输出的 `config.yaml` 路径。与 `config.yaml` 同级的 `skills` 文件夹就是安装目录；如果没有 `skills` 文件夹，请新建一个。
4. 打开解压目录中的 `skills` 文件夹。
5. 将下面 5 个完整文件夹复制到 Hermes 的 `skills` 文件夹：

```text
facebook-daily-like
facebook-daily-comment
facebook-followed-video-download
cloudflare-r2-video-upload
facebook-video-ingest
```

安装后的结构必须类似：

```text
<Hermes目录>\skills\facebook-daily-like\SKILL.md
<Hermes目录>\skills\facebook-daily-comment\SKILL.md
<Hermes目录>\skills\facebook-followed-video-download\SKILL.md
<Hermes目录>\skills\cloudflare-r2-video-upload\SKILL.md
<Hermes目录>\skills\facebook-video-ingest\SKILL.md
```

不要把外层 `operation-skill` 或 `skills` 文件夹整体当成一个 Skill。

#### macOS

1. 双击 ZIP 解压。
2. 在终端运行：

```bash
hermes config path
```

3. 记下输出的 `config.yaml` 路径。与 `config.yaml` 同级的 `skills` 文件夹就是安装目录。
4. 在 Finder 中按 `Command + Shift + G`，输入该目录路径并打开。
5. 如果没有 `skills` 文件夹，请新建一个。
6. 从解压包的 `skills` 目录中，将下面 5 个完整文件夹复制进去：

```text
facebook-daily-like
facebook-daily-comment
facebook-followed-video-download
cloudflare-r2-video-upload
facebook-video-ingest
```

安装后的结构必须类似：

```text
<Hermes目录>/skills/facebook-daily-like/SKILL.md
<Hermes目录>/skills/facebook-daily-comment/SKILL.md
<Hermes目录>/skills/facebook-followed-video-download/SKILL.md
<Hermes目录>/skills/cloudflare-r2-video-upload/SKILL.md
<Hermes目录>/skills/facebook-video-ingest/SKILL.md
```

#### ZIP 安装完成后的检查

重新启动 Hermes，或在现有聊天中输入：

```text
/reload-skills
```

然后分别输入以下命令，确认 Hermes 能识别：

```text
/facebook-daily-like
/facebook-daily-comment
/facebook-followed-video-download
/cloudflare-r2-video-upload
/facebook-video-ingest
```

如果提示 Skill 不存在，优先检查是否多套了一层目录，以及每个 Skill 文件夹里是否直接存在 `SKILL.md`。

## 五、运营通用操作规则

1. 打开 PowerShell 或终端，运行 `hermes`。
2. 每次任务都明确写出目标设备或文件夹、数量和操作内容。
3. 检查或预演时明确写“只预演，不要执行”。
4. 真正操作时明确写“立即执行”。
5. Hermes 正在执行时不要重复发送同一任务。
6. 下载和上传可能运行较久。只要仍有进度，就继续等待，不要重新启动。
7. 任务部分完成时，只补剩余数量，不要重新执行原始总数量。
8. 不要在 Hermes 聊天中发送账号密码、验证码、API Key、R2 Secret、Cookie 内容。
9. Facebook 登录、验证码、安全检查必须在云手机中人工完成。
10. 先用小数量试运行，确认正常后再扩大数量。

## 六、Facebook 每日点赞

用途：让指定 MYT 云手机给 Facebook 动态点赞。

### 6.1 首次检查

```text
/facebook-daily-like 检查 T1001 和 T1002 的连接，不要点赞
```

看到每台设备连接正常后再继续。如果连接失败，联系管理员。

### 6.2 预演

```text
/facebook-daily-like 为 T1001 和 T1002 各查找 5 篇可点赞动态，只预演，不要执行
```

预演只查找按钮，不会真正点赞。

### 6.3 正式执行

```text
/facebook-daily-like 给 T1001 和 T1002 各点赞 5 篇，立即执行
```

将设备编号和数量替换为当天任务要求。多个设备可以写在一句话中。

### 6.4 查看结果与补跑

正常完成时，每台设备的点赞数应达到目标。

例如 T1001 原目标为 5，结果只完成 3，剩余 2：

```text
/facebook-daily-like 只给 T1001 补点赞 2 篇，立即执行
```

不要再次要求 T1001 点赞 5 篇。任务运行较久不代表失败，不要重复启动。

## 七、Facebook 每日评论

用途：让指定 MYT 云手机在 Facebook 动态下发表评论。

评论内容默认只支持英文、数字和常见英文标点，不支持中文、Emoji 或换行。建议使用 `Nice post!`、`Thanks for sharing.` 等内容。

### 7.1 首次检查

```text
/facebook-daily-comment 检查 T1001 和 T1002 的连接，不要评论
```

### 7.2 预演

```text
/facebook-daily-comment 为 T1001 和 T1002 各查找 3 篇可评论动态，评论内容为 Nice post!，只预演，不要执行
```

预演不会输入或发送评论。

### 7.3 正式执行

```text
/facebook-daily-comment 给 T1001 和 T1002 各评论 3 篇，内容为 Nice post!，立即执行
```

必须同时写明：

- 设备编号；
- 每台评论数量；
- 完整评论内容；
- “立即执行”。

### 7.4 查看结果与补跑

只有结果显示评论已验证成功，才算完成。

例如 T1001 原目标为 3，结果显示完成 2、剩余 1：

```text
/facebook-daily-comment 只给 T1001 补评论 1 篇，内容仍为 Nice post!，立即执行
```

如果结果出现 `unverified-send`，表示可能已经发送但系统无法确认。必须先人工打开对应云手机检查评论是否存在，确认后再决定是否补跑，不能直接重复执行。

如果结果显示跳过重复帖子，这是正常的防重复保护，不要要求在同一帖子上强制重复评论。

## 八、Facebook 关注来源视频下载

用途：从已授权的 Facebook Page、创作者、Reels 或视频链接查找并下载新视频。

默认保存位置：

- Windows：当前用户桌面的 `Facebook` 文件夹。
- macOS：当前用户桌面的 `Facebook` 文件夹。

只允许下载公开内容或已明确获准保存的内容。不要尝试绕过私人页面、付费内容、登录限制或 DRM。

### 8.1 检查是否可用

```text
/facebook-followed-video-download 检查下载功能是否准备完成，不要下载
```

如果提示缺少 Chrome、Node.js、`yt-dlp` 或来源配置，联系管理员。

### 8.2 首次初始化来源

```text
/facebook-followed-video-download 初始化来源配置
```

### 8.3 添加来源

```text
/facebook-followed-video-download 添加来源 creator-one，地址为 https://www.facebook.com/example/reels/
```

将 `creator-one` 改成便于识别的英文目录名，将网址改成实际获准使用的 Facebook 来源。

添加多个来源时，每个来源分别发送一次。

### 8.4 查看当前来源

```text
/facebook-followed-video-download 列出当前所有来源
```

### 8.5 预演最新视频

```text
/facebook-followed-video-download 查找每个来源最新 3 个视频，详细预演，不要下载
```

### 8.6 下载最新视频

```text
/facebook-followed-video-download 下载每个来源最新 3 个视频，立即执行
```

“每个来源 3 个”表示每一个来源最多下载 3 个，不是全部来源合计 3 个。

### 8.7 首次全量下载

全量下载可能耗时很长、占用大量磁盘空间。确认磁盘空间足够后再执行：

```text
/facebook-followed-video-download 首次全量下载所有来源，不限制数量，立即执行
```

下载工具会自动避免重复下载。任务长时间运行时继续等待，不要重复发送下载命令。

多个定时抓取任务使用同一个 Chrome 配置时，应尽量错开执行时间。若仍发生重叠，下载工具会自动排队等待前一个任务结束，不需要再次手动启动；`Chrome CDP did not start` 通常表示旧版本发生了并发争用，应升级到 1.6.2 或更高版本。

## 九、Cloudflare R2 视频上传

用途：把本地视频上传到管理员已配置好的 Cloudflare R2 存储桶。

上传不会删除本地文件。同名且大小相同的文件会自动跳过；同名但大小不同会报告冲突，默认不会覆盖。

### 9.1 检查连接

```text
/cloudflare-r2-video-upload 检查 R2 配置和存储桶连接，不要上传
```

如果提示凭据或存储桶缺失，联系管理员，不要在聊天中发送 Secret Key。

### 9.2 Windows 预演

```text
/cloudflare-r2-video-upload 检查 C:\Users\你的用户名\Desktop\Facebook 下准备上传的前 10 个视频，R2 前缀为 facebook，不要上传
```

### 9.3 Windows 正式上传

```text
/cloudflare-r2-video-upload 把 C:\Users\你的用户名\Desktop\Facebook 下全部视频上传到 R2 的 facebook 前缀，并发 3 个，立即执行
```

### 9.4 macOS 预演

```text
/cloudflare-r2-video-upload 检查 /Users/你的用户名/Desktop/Facebook 下准备上传的前 10 个视频，R2 前缀为 facebook，不要上传
```

### 9.5 macOS 正式上传

```text
/cloudflare-r2-video-upload 把 /Users/你的用户名/Desktop/Facebook 下全部视频上传到 R2 的 facebook 前缀，并发 3 个，立即执行
```

### 9.6 上传单个文件

Windows 示例：

```text
/cloudflare-r2-video-upload 把 C:\Users\你的用户名\Desktop\Facebook\video.mp4 上传到 R2 的 facebook 前缀，立即执行
```

macOS 示例：

```text
/cloudflare-r2-video-upload 把 /Users/你的用户名/Desktop/Facebook/video.mp4 上传到 R2 的 facebook 前缀，立即执行
```

### 9.7 查看结果

完成后重点查看：

- `uploaded`：成功上传数量；
- `skipped-existing`：远端已有相同文件，已跳过；
- `conflict`：远端同名文件大小不同，未覆盖；
- `failed`：上传失败数量。

如果出现 `conflict`，先核对本地和远端文件。只有负责人明确同意覆盖后，才告诉 Hermes“允许覆盖同名但大小不同的文件并立即执行”。

大型视频上传可能持续很久。只要仍有上传进度，就等待同一任务完成，不要再次启动。

## 十、后台自动视频入库

用途：由后台统一安排抓取时间，Hermes 自动认领任务、下载视频、上传 R2，并把每个视频的本地文件和 R2 结果记录回后台。

此功能由后台按每个抓取时间段自动创建或更新 Hermes Cron 定时任务。运营人员不要在 Hermes 中手工复制同名任务，也不要同时启动第二个相同 Worker。

首次检查：

```text
/facebook-video-ingest 检查后台、下载器和 R2 Worker 是否准备完成，不要认领任务
```

管理员进行单条验收时：

```text
/facebook-video-ingest 认领并完整执行一条后台视频抓取任务
```

日常使用只需在后台创建 Facebook 抓取任务、配置时间段，或点击“立即执行”。任务详情会显示下载状态、本地路径、文件大小、SHA-256、R2 存储桶、对象键和地址；执行历史会显示 Worker、心跳、进度及错误。

出现 `no-work` 表示当前没有待执行任务，不是故障。出现 Worker Token、R2 凭据、后台连接或租约错误时，联系管理员，不要把任何 Token 或 Secret 发到聊天中。

## 十一、常见问题处理

| 情况 | 运营处理方式 |
|---|---|
| `hermes` 命令不存在 | 关闭并重新打开 PowerShell/终端；仍失败则联系管理员 |
| 模型返回 `401` 或 `403` | API Key 无效或无权限，联系管理员 |
| 模型返回 `404` 或 model not found | 截图错误，联系管理员检查 URL 和模型名称 |
| 找不到 Skill | 输入 `/reload-skills`；仍失败则检查 ZIP 目录层级或重新进行仓库安装 |
| MYT 设备连接失败 | 检查设备编号和网络，联系管理员 |
| Facebook 要求登录或验证码 | 在云手机中人工处理，不能让 Hermes 绕过 |
| 点赞或评论只完成一部分 | 只按结果中的剩余数量补跑 |
| 评论出现 `unverified-send` | 先人工检查云手机，不能直接重跑 |
| 下载或上传长时间运行 | 只要仍有进度就继续等待，不要重复启动 |
| 视频下载提示依赖缺失 | 联系管理员安装 Chrome、Node.js、`yt-dlp` 等依赖 |
| R2 提示凭据缺失 | 联系管理员配置，不能把密钥发到聊天窗口 |
| R2 显示 `conflict` | 先核对文件，未经负责人许可不要覆盖 |

## 十一、每日建议操作顺序

1. 打开 PowerShell 或终端，运行 `hermes`。
2. 点赞或评论前先检查 MYT 连接。
3. 先用少量任务预演。
4. 确认预演正常后发送带“立即执行”的正式任务。
